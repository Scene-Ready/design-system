# ADR 0001: Tokens and the `dark:` variant follow the OS when no `data-theme` is set

- **Status:** Accepted
- **Date:** 2026-11-24
- **Issue:** [design-system#14](https://github.com/Scene-Ready/design-system/issues/14)
- **Release:** v0.8.0 (minor)

## Context

Up to v0.7.0, `tokens.css` switched to dark only on `data-theme="dark"`, and `tailwind.css` declared no `dark:` variant, so each Tailwind app chose its own. They disagreed:

- learn followed the OS through `light-dark()`.
- portal's `dark:` utilities followed the OS (Tailwind's default) while its tokens stayed light, so it rendered half dark.
- rigprep-sim declared its own `data-theme` variant.
- scenario-prep used a `.dark` class.

## Decision

One rule, owned by the design system, for both the tokens and the `dark:` variant:

| `data-theme` | Theme |
|---|---|
| none | follows `prefers-color-scheme` |
| `dark` on an element | dark for it and its descendants |
| `light` on `<html>` | light |

- `tokens.css` keeps the dark aliases in `[data-theme='dark']` and repeats them inside `@media (prefers-color-scheme: dark)` for `:root:not([data-theme='light'])`. The copy is generated by `npm run sync-dark`, and `npm run check` fails if the two differ, so nobody edits two sets of values.
- `tailwind.css` declares `@custom-variant dark`: `[data-theme='dark']` and its descendants, or the OS is dark and no ancestor has `data-theme='light'`. Apps declare no variant of their own.
- An app with a theme setting sets `data-theme` to the resolved `light` or `dark`. An app that follows the OS sets nothing. **An app with no dark mode must pin `data-theme="light"` on `<html>`.**

## Consequences

- Every app's tokens and `dark:` utilities switch together; the half-dark state can't happen.
- Following the OS is the default, which matches §9.4's "default to the OS until the user picks a theme" without per-app code.
- Breaking for apps with no dark mode: without the light pin they go dark on dark-mode machines. The README upgrade note says so, and it ships as a minor release (pre-1.0).
- `data-theme="light"` is honored on `<html>` only for the tokens (the OS copy is scoped to `:root`). A light region inside a dark page is not supported; a dark region inside a light page is.
- The dark values exist twice in `tokens.css`; the generator and check keep that safe.

### Apps, on upgrade

| App | Change |
|---|---|
| auth, scene-ready-app | Pin `data-theme="light"` (tracked in their repos) |
| scenario-prep | Do #270 (`.dark` class → `data-theme`) in the same PR |
| rigprep-sim | Drop its own `@custom-variant dark` (rigprep-sim#441) |
| learn | Drop `light-dark()` (learn#8) |
| portal, feedback, quarters | No change; portal keeps following the OS with no theme setting |

## Alternatives considered

- **`light-dark()` in `tokens.css`.** One copy of each value, but no way for `data-theme` to force a theme without also setting `color-scheme`, side effects on form controls and scrollbars, and Tailwind's `dark:` would still need its own rule.
- **Keep `data-theme` only, and make the variant match.** Fixes portal's half-dark render, but every OS-following app would need a script to set the attribute.
